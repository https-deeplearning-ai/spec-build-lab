Lesson 5 — The Automation Loop

Two simulated tools, one automation loop

This is a stand-in for a real Jira + Confluence setup, so the lesson runs with no accounts and no API tokens. The same Requirements Analysis Agent from Lessons 3-4 sits behind both.

  • Confluence holds the requirement document. It is the source of truth, and the agent only ever reads it.
  • Jira holds the ticket. Creating a ticket, or editing the linked requirement page while a ticket is open, triggers the agent automatically.

Try this: open the ticket below, then open its linked Confluence page and edit the requirement. Save it, then come back to the ticket — the analysis re-ran on its own.
